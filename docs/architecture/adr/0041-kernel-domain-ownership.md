# ADR 0041: Kernel domain ownership and explicit context fusion

Status: implemented; release verification is recorded separately.

JARVIS belongs to a principal. A business integration does not define that principal or the assistant's identity. Domain instances belong to one principal and have a kind: PERSONAL, BUSINESS, PROJECT, FINANCIAL or SYSTEM. Names and IDs are operator data; unrelated activities require no reasoning-policy changes.

The existing PostgreSQL authority stores the domain ledger, per-node selections, immutable correlation bindings and expiring fusion grants. Migration `0018_domains.sql` adds ownership to objectives, ATLAS, MNEMOSYNE, cognitive runs/jobs, grants, invocations, authority tokens, credential handles, conversation turns and events. Composite foreign keys enforce principal ownership. Child-resource triggers reject mismatched objective, agent, entity, relationship and conversation boundaries. There is no parallel authoritative database.

Authenticated workstation management uses `/domains`. Domain selection uses compare-and-set versions. A principal, domain and purpose are bound to each correlation before cognition or agency. Agents cannot create that authority through proposal fields. Policy, Permission, Approval, Executor and Verification remain responsible for effects; a domain selection or fusion grant is not an execution grant. Node trust and credential scopes remain independent requirements.

Context retrieval filters by owner and allowed domains before ranking, limits and omission summaries. A source domain requires an explicit, unexpired, unrevoked grant for the exact target and purpose. Cross-domain BUSINESS and FINANCIAL retrieval permits only PUBLIC material. Other source domains permit at most INTERNAL material. Private financial context is excluded from research/coding even within its domain. Fusion confers retrieval only; source-domain writes are excluded. Secret references are opaque, never model context. The Credential Broker checks invocation, grant/token ownership and the secret reference; financial credentials require financial-purpose invocations.

Conversations reject reuse in another domain. Voice histories, screen selections and expiring research evidence retain their domain. Correlation identity, job hashes and response ownership prevent replay into another domain. Persisted objectives supply scoped context; unclassified global ambient state is excluded. Knowledge Ingestion remains the sole durable knowledge writer, and harvesting/consolidation partitions work by domain.

Compatibility is additive. Optional wire fields allow old callers to default to PERSONAL. Existing ambiguous persisted records are retained in each owner's SYSTEM quarantine; their original contents and provenance remain intact. They are not silently attributed to a business or imported into new personal conversations. Existing pre-migration jobs cannot be resumed as PERSONAL jobs using the same IDs. Integration configuration explicitly supplies domain definitions and grants. ScaleSmiths has a BUSINESS adapter default; personal email/calendar stay PERSONAL unless the operator explicitly assigns the business account to the integration domain.

This is an application-enforced Kernel boundary backed by database ownership constraints, not PostgreSQL RLS isolation against a compromised database administrator. Administrator SQL remains trusted. Provider accounts are currently configured once per provider/principal; simultaneous separate accounts require further adapter work. No visual domain selector or interface changes are included. Controlled model/provider fixtures establish routing and privacy behavior, not live model quality or provider access.
