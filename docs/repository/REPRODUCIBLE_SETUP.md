# Reproducible setup and build

The qualified JavaScript toolchain is **Node 22.19.0**, **pnpm 9.15.9** and
**TypeScript 5.6.3**. `.node-version` drives both CI platforms; `packageManager`
pins pnpm; `pnpm-lock.yaml` format 9 pins the resolved graph. The broad Node
engine declaration is a compatibility floor, not qualification of every newer
Node version. Update the Node pin deliberately and rerun both jobs.

## Windows

Install Node 22.19.0 for your architecture, Git and pnpm 9.15.9. With Corepack
available, run `corepack enable` and `corepack prepare pnpm@9.15.9 --activate`.
Use PowerShell from the checkout root:

```powershell
pnpm setup:check
pnpm install --frozen-lockfile
pnpm setup:check --installed --full
pnpm assets:check
pnpm verify:full
```

Docker Desktop must be running with its **Linux** engine (WSL2), not Windows
containers. Test containers bind disposable loopback ports; no production
database or provider credentials are needed. A stopped Docker daemon is a
failure, not a reason to skip integration, chaos or restore verification.
Allow sufficient RAM/disk for Docker, Next and the package store. Windows unit
workers are bounded to two and integration workers to one by default.

## Linux

Install Git, Node 22.19.0, pnpm 9.15.9 and Docker Engine with permission to run
containers. Run the same five pnpm commands above from Bash. CI uses a fresh
Ubuntu checkout and frozen installation, runs every release gate, and retains
generated qualification reports for 14 days. A second fresh Windows CI checkout
installs, checks assets, typechecks, runs unit tests and builds the desktop.

The repository's hoisted pnpm linker is intentional for Windows filesystem
cost; do not substitute npm/yarn or regenerate the lockfile with another pnpm
major. `pnpm deps:audit` reports actual static imports and package-script
references. `pnpm why -r <package>` shows peer/transitive ownership.

## Assets and clean checkout

`pnpm assets:check` verifies SHA-256 pins for 109 retained runtime assets,
native icons, shader files and static visual references. All 48 curated static
screenshots keep their existing paths. They are manual review references;
there is currently **no checked-in automated pixel-comparison runner**.
The two historical visual check reports remain tracked and do not certify a
new commit's appearance.

MediaPipe model/WASM files under `apps/vision/public/assets/mediapipe` are
required runtime dependencies, not disposable binaries. The desktop's existing
Next configuration copies these into its ignored public asset directory during
build. `pnpm vision:assets` can verify/provision them against the existing
runtime pins. Next's `out/` is regenerated by `pnpm build:desktop`; it is not
required in Git, including for Tauri's `frontendDist`.

## Native builds are a separate qualification

`pnpm build:desktop` produces the **Next static export**, not an installed Tauri
binary. Tauri v2 also needs Rust/Cargo, the committed Cargo.lock and native
platform prerequisites. Use `pnpm setup:check --native` to detect available
tools, then run `cargo build --locked --manifest-path apps/desktop/src-tauri/Cargo.toml`
after the frontend build, or `pnpm --filter @jarvis/desktop exec tauri build`.
Do not confuse an availability check with successful linking or hardware use.

Windows needs MSVC C++ build tools, Windows SDK and Edge WebView2. Ubuntu/Debian
native development needs `build-essential`, `pkg-config`, `libwebkit2gtk-4.1-dev`,
`libgtk-3-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`, `libssl-dev` and
`patchelf`. Follow the [official Tauri prerequisites](https://v2.tauri.app/start/prerequisites/)
for your distribution/architecture. Rust 1.98.1 is present on this workstation;
native Rust compilation is not pinned or certified by the JavaScript CI jobs.
Cross-architecture native packages remain separate live/build qualification.

Android is also separate: JDK 17, Gradle 8.11.1, AGP 8.9.2, Kotlin 2.1.20,
Android platform 35/build-tools 35.0.0. The existing isolated
`apps/mobile/android/build-in-container.sh` copies generated APK/lint reports
to a writable output mount, conventionally `artifacts/companion/`. It verifies
the Gradle download checksum; it still depends on SDK/network downloads and
is not a hermetic or mandatory CI Android build. Device installation is unproven.

## Credentials and remaining verification

A clean checkout contains no `.env` or private integration configuration. Tests
use controlled fixtures and real disposable infrastructure; live providers,
physical microphone/camera, GPU/browser pixel output, Tauri installation,
Android permissions and cross-machine continuity still require qualification.
See [RELEASE_BASELINE](../architecture/RELEASE_BASELINE.md). No application,
visual, permission or provider behavior is changed by this hygiene work.
